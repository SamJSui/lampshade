# Lampshade 0.9 release validation

Date: 2026-08-11

Lampshade 0.9 passes the published-release regression budget after one targeted
recheck and validates the same implementation package on discrete NVIDIA,
integrated NVIDIA, Intel integrated, and Apple Silicon GPUs.

## Correctness matrix

The source package used on every remote host had SHA-256
`2f7dbd346015dde086e80c0487862c1f6bc3848fec3bff47118e9121b343ab97`.
Each host ran the release library and integration suite serially: 118 tests
passed, with the normal 100M validator ignored in that command. The ignored
100M adapter-selected `u32` sort validator then passed separately.

| Adapter | Backend | Release suite | 100M sort |
| --- | --- | ---: | ---: |
| NVIDIA GeForce RTX 4070 Ti SUPER, driver 591.86 | Vulkan | pass | pass |
| NVIDIA Jetson Orin (`nvgpu`), driver 595.78 | Vulkan | pass | pass |
| Intel Alder Lake-N | Vulkan | pass | pass |
| Apple M3 Pro | Metal | pass | pass |

Apple Metal timestamp profiling remains disabled because stage-boundary query
pairs were incomplete. The Jetson run found a second backend-sensitive issue:
repeated compute/readback calls could return recycled data when optional
subgroup or timestamp-query features were enabled, or when a staging buffer was
mapped before its copy had explicitly completed. The 0.9 convenience context
therefore requests neither optional feature on integrated NVIDIA Vulkan, and
readback now completes the device-local copy before starting the map. Profiling
is unavailable through that convenience context on Jetson; resident wall-time
benchmarks still work.

## Published 0.8 regression gate

The formal RTX harness compared identical public resident operations and
completion boundaries against crates.io Lampshade 0.8. It used three
independent processes for all 15 workload/size rows and a 2% candidate budget.

- Initial result: 14/15 rows passed.
- Only miss: 10M sum reduction, +3.62% (0.1021 ms to 0.1058 ms).
- Required nine-process recheck: pass at -0.10% (0.1003 ms to 0.1002 ms).
- Every 100M row passed initially; changes ranged from -0.12% to +0.52%.
- Full-width 100M key/value sort changed +0.18% (14.5221 ms to 14.5482 ms).

The initial and recheck JSON files preserve all raw runs, adapter identities,
commands, and the 78-file source manifest:

## Key-only sort characterization

The fixed-length `u32` path was validated before timing. Five independent
processes used five samples and a one-second warm-up. The table reports the
median of process medians on the RTX Vulkan adapter.

| Items | Resident wall | GPU elapsed | Throughput from wall |
| ---: | ---: | ---: | ---: |
| 1M | 0.339 ms | 0.274 ms | 2.95 Gelem/s |
| 10M | 1.453 ms | 1.363 ms | 6.88 Gelem/s |
| 100M | 12.558 ms | 12.270 ms | 7.96 Gelem/s |

At 100M, scatter accounts for about 94% of GPU time. This is characterization
of the 0.9 candidate, not a new cross-library comparison.

## Run-length encoding characterization

Criterion measured sorted inputs with average run length eight. Each of three
independent processes validated complete fixed and counted outputs before
timing. Timed work includes recording, submission, execution, and completion;
upload and readback are excluded.

| Items | Fixed | GPU-counted dense | Counted change | Fixed throughput |
| ---: | ---: | ---: | ---: | ---: |
| 1M | 0.197 ms | 0.195 ms | -0.82% | 5.08 Gelem/s |
| 10M | 0.802 ms | 0.805 ms | +0.32% | 12.46 Gelem/s |
| 100M | 7.225 ms | 7.223 ms | -0.04% | 13.84 Gelem/s |

The counted path is effectively tied with fixed RLE at all three sizes. The
0.9 RLE rewrite uses one dense binding set and separate mark, scatter, and
finalize stages. No matched external RLE baseline exists yet, so these numbers
must not be presented as a competitor speedup.
