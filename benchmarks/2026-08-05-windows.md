# Windows RTX 4070 Ti SUPER Benchmark

These measurements characterize the v0.2 GPU-buffer and convenience APIs. They are not kernel-only timestamps.

## System

- GPU: NVIDIA GeForce RTX 4070 Ti SUPER
- CPU: AMD Ryzen 7 7800X3D, 8 cores and 16 logical processors
- Memory: 32 GB
- OS: Windows 11 Education 10.0.26200, 64-bit
- wgpu: 28.0.0
- Criterion: 0.8.2
- Vulkan driver: NVIDIA 591.86
- DX12 driver: 32.0.15.9186

## Method

Inputs use a deterministic seed mixed with the item count. Cases through 1M use 30 samples and a 5-second measurement window. Cases from 10M use 10 samples and a 15-second window. Criterion extends a window when necessary.

- `cpu_scalar` scans into a reusable CPU output allocation.
- `cpu_rayon` excludes the input clone from timing and uses `par_sort_unstable`.
- `cpu_rayon_stable` excludes the input clone from timing and uses `par_sort_by_key` over duplicate-heavy `KeyValue` items.
- `gpu_resident` uses caller-owned buffers, then waits for submitted GPU work. It includes command encoding, submission, and the primitive's internal workspace management, but excludes host transfer.
- `gpu_round_trip` includes input upload, temporary buffer allocation, GPU execution, staging readback, and output allocation.

Reported values are Criterion regression-slope point estimates with 95% confidence intervals. Throughput is calculated from the point estimate.

### Exclusive Scan Follow-up

The exclusive scan implementation uses a separately compiled leaf pipeline while retaining inclusive block-sum scans for the hierarchy. It therefore has the same dispatch count and scratch-memory requirement as the inclusive path. A focused 100M-item DX12 run used the same 10-sample, 15-second Criterion configuration as the original large-input matrix.

| Items | Backend | Path | Time, ms (95% CI) | Billion elements/s |
| ---: | --- | --- | ---: | ---: |
| 100M | CPU | Scalar exclusive | 28.580 (28.395-28.722) | 3.499 |
| 100M | DX12 | GPU resident exclusive | 6.238 (6.234-6.242) | 16.030 |

At 100M items, resident exclusive scan was 4.58x faster than the matching scalar CPU implementation. Round-trip exclusive scan was not measured in this focused follow-up.

## Stable Key-Value Radix Sort

Key-value inputs contain an interleaved `u32` key and `u32` value. Keys are limited to 16 random bits to create duplicates, and values contain original positions so correctness tests can verify stability. The GPU carries each value through all 16 radix passes with its key.

| Items | Backend | Path | Time, ms (95% CI) | Billion pairs/s |
| ---: | --- | --- | ---: | ---: |
| 10M | CPU | Stable Rayon | 51.783 (50.342-54.025) | 0.193 |
| 10M | Vulkan | GPU resident | 12.694 (12.619-12.812) | 0.788 |
| 10M | Vulkan | GPU round trip | 34.142 (33.934-34.346) | 0.293 |
| 100M | CPU | Stable Rayon | 687.590 (683.970-691.700) | 0.145 |
| 100M | Vulkan | GPU resident | 110.270 (109.620-110.790) | 0.907 |
| 100M | Vulkan | GPU round trip | 576.340 (533.300-628.150) | 0.174 |

At 100M pairs, resident key-value sort was 6.23x faster than stable Rayon. The full upload, allocation, execution, and readback path was 1.19x faster. A post-refactor key-only regression check measured 44.041 ms at 100M keys, with Criterion reporting no statistically significant performance change.

## Memory

At 100M `u32` values, caller-owned input and output buffers total 800,000,000 bytes (762.9 MiB).

- Prefix scan retains 195,840 bytes (191.25 KiB) of internal scratch storage.
- Radix sort retains approximately 404,226,816 bytes (385.5 MiB) for ping-pong scratch, histograms, and histogram-scan scratch.
- Radix sort also creates a small aligned uniform buffer per invocation. Bind groups and driver-managed allocations are not included.
- Stable key-value sort retains approximately 807,075,072 bytes (769.7 MiB) for pair scratch, histograms, histogram-scan scratch, and scan scratch at 100M pairs.

The memory figures follow the allocation formulas used by the v0.2 implementation with `VT=8` and a workgroup size of 256 on this adapter.

## Reproduction

Set `WGPU_BACKEND` to `vulkan` or `dx12`, then run:

```sh
cargo bench --bench scan -- --noplot
cargo bench --bench sort -- --noplot
```
